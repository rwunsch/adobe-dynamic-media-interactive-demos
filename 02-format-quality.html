Same URL, fewer bytes — automatically

Smart Imaging converts each delivery to the best modern format the visitor's browser accepts (AVIF / WebP) at an optimized quality — no URL change, no code. Below, the same request is served with Smart Imaging off (bfc=off → baseline JPEG) and on (bfc=on). Both are fetched live by your browser. Drag quality and watch the bytes on both sides move.

The toggle

bfc = "browser format conversion" — the one switch that turns Smart Imaging on or off per request. bfc=off forces baseline JPEG; it's here to reveal what Smart Imaging is doing for you on every other URL.

bfc=on is stated explicitly on the right-hand URL. On most accounts Smart Imaging is already the default, but on a custom domain / CDN mapping where it hasn't been enabled, the explicit bfc=on guarantees the optimized delivery.

The single authored URL (Smart Imaging on)

Quality still applies in both modes — Smart Imaging additionally swaps the format to AVIF/WebP per the browser's Accept header, which is where most of the saving comes from. Every unique URL is rendered once, then edge-cached.

Both tiles above are plain <img src="…"> elements pointing at the real delivery URLs — open DevTools → Network, or right-click → "Open image in new tab", to inspect the actual request and its response headers. The KB and format readouts come from a parallel measuring request to the same URL, kept in a hidden probe element.
